File format and lookup rules

A catalog is a JSON object per locale. This page lists what locjson accepts in that object, what it rejects at load time, and how t() walks from a requested locale to a string.

1Layouts

Both layouts are detected automatically. Pick one per locale.

single file per locale · namespacedtree
locales/                     locales/
├── en.json                  ├── en/
└── tr.json                  │   ├── common.json   → keys "common.*"
                             │   └── inbox.json    → keys "inbox.*"
                             └── tr/
                                 ├── common.json
                                 └── inbox.json

In the namespaced layout, each file name becomes the first segment of its keys. A locale present in both layouts (en.json and en/) is an error that names both paths.

2Keys and values

JSONMeaning
{"nav": {"home": "Home"}}Nested objects flatten to dot keys: t("nav.home").
"Hello, {name}!"A translation. Values must be strings.
"" or nullUntranslated. The lookup falls through to the next locale in the chain.
{"zero": …, "one": …, "other": …}A plural entry. See plural entries.
{"$plural": false, "one": …, "other": …}Forces an object that looks like a plural entry to be read as a normal group.
"$meta" (top level)File metadata, never a translation.
"$comment" and other $ keysIgnored. Handy for notes to translators.

3Plural entries

An object is a plural entry when every key is a CLDR category (zero, one, two, few, many, other), other is present, and every value is a string.

locales/tr.jsonJSON
{
  "inbox": {
    "messages": {
      "zero": "Hiç mesajınız yok",
      "one": "{count} mesajınız var",
      "other": "{count} mesajınız var"
    }
  }
}
  • count is passed to the template automatically, so {count} just works.
  • When count == 0 and the entry has a zero form, zero is used in every language.
  • Otherwise the language's plural category is used, falling back to other. In 0.1 this is a simple one/other rule. CLDR rules for 17 built-in languages are planned for 0.2.

The resolver on the front page shows both: the 0.1 rule, and a preview of the planned CLDR rules for Arabic's six forms.

4$meta

$meta describes the file it sits in.

locales/ar.jsonJSON
{
  "$meta": { "locale": "ar", "direction": "rtl" },
  "greeting": "مرحبًا، {name}!"
}

locale must match the file's locale, direction is "ltr" or "rtl", and unknown $meta keys are rejected.

5Rejected at load

These raise InvalidCatalogError when the catalog is loaded, with the file path and a JSON pointer to the problem:

  • numbers, booleans and arrays as values
  • duplicate keys
  • NaN and Infinity
  • key-path collisions

Files are read as UTF-8 and a BOM is accepted, so non-ASCII text such as Turkish İ and ı round-trips unchanged.

6Interpolation

Placeholders are named fields only, compiled once when the catalog loads.

TemplateResult
"Hello, {name}!"t("greeting", name="Enes") gives Hello, Enes!
"Use {{name}} for a placeholder"Use {name} for a placeholder. Doubled braces are literal.
{0}, {user.name}, {items[0]}Rejected at load.
{price:.2f}, {value!r}Rejected at load. No format specs or conversions.

Format values in Python before passing them in, for example t("total", price=f"{price:.2f}").

If a variable is not passed, the placeholder stays as literal {name} text and a debug record is logged on the locjson logger. With missing="raise", an InterpolationError is raised instead.

7Locale tags

Locale tags are normalized to BCP 47, so pt_BR, tr_TR.UTF-8 and zh-hant-tw become pt-BR, tr-TR and zh-Hant-TW. Legacy codes are mapped (iw → he).

Invalid tags raise InvalidLocaleError when passed to the constructor. At request time (t(locale=...), use(...)) they fall back to default_locale instead of failing.

current locale, negotiation, directionPython
with l10n.use("tr"):        # scoped: the previous locale is restored on exit
    l10n.t("nav.home")      # 'Ana sayfa'

l10n.set_locale("tr")       # for the current context, e.g. one request
l10n.current_locale         # 'tr'

l10n.negotiate("tr-TR,tr;q=0.9,en;q=0.8")  # 'tr', best match from Accept-Language
l10n.direction("ar")                       # 'rtl'

The current locale lives in a ContextVar per Localizer, so each asyncio task and thread sees its own value.

8Fallback chain

For a requested locale the lookup chain is: the locale itself, then its explicit fallbacks, then its parents, then default_locale. Parents are script-aware, so Traditional Chinese never falls back to Simplified.

RequestedChain with default_locale="en", fallbacks={"pt-BR": ["pt"]}
pt-BRpt-BR → pt → en
tr-CYtr-CY → tr → en
zh-TWzh-TW → zh-Hant → en
zh-Hans-CNzh-Hans-CN → zh-Hans → zh → en

A key whose value is "" or null counts as untranslated, so the lookup moves on to the next locale in the chain.

9Missing translations

missing=When a key is missing in the whole chain
"key" (default)Returns the key, e.g. "nav.profile".
"empty"Returns "".
"raise"Raises MissingTranslationError, and makes missing variables and a missing count raise too.
callable(key, locale)Returns whatever your function returns.

Every slip is logged at DEBUG level on the locjson logger, so you can surface them in development without noise in production.

10Errors

All exceptions inherit from LocJsonError.

ExceptionRaised when
ConfigurationErrorThe Localizer is misconfigured, e.g. neither path nor loader is given.
InvalidLocaleErrorA locale tag in the configuration is invalid.
InvalidCatalogErrorA catalog file is invalid. Exposes .path and .pointer (RFC 6901).
MissingTranslationErrorA key is missing under missing="raise". Also a LookupError.
InterpolationErrorA variable or count is missing under missing="raise".
